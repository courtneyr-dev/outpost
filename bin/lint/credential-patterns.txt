# Section 5 audit — credential heuristics (B2).
#
# ERE-compatible regexes matching obvious credential patterns. One per
# line. Comments and blank lines ignored.
#
# Suppression: lines tagged with the marker
#     /* outpost-lint:fixture-credential */
# are exempt — for use in test fixtures that intentionally embed
# fake-but-real-shaped credentials (e.g. AES-GCM key bytes for token
# store unit tests).
#
# These patterns target SHAPE not entropy. Generic high-entropy strings
# are not flagged because minified bundles, hashes, and URL-safe
# encoded blobs all look high-entropy and would generate false positives.
# When a real leak doesn't match these patterns, the right move is to
# add a new pattern here (with a session-log entry documenting why),
# not to widen to entropy-based heuristics.

(api[_-]?key|client[_-]?secret|access[_-]?token|bearer)[[:space:]]*[=:][[:space:]]*['"][A-Za-z0-9_-]{16,}['"]
