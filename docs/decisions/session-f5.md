## Session F5 — Locked Decisions (shipped)

Closed 2026-05-04. Inbound source-adapter foundation. Defines `Outpost_Source_Base` (mirrors F1+F2's `Outpost_Companion_Base` inverted), the registry, the URL-pattern matcher, the seven extractor types (one concrete, six stubs), and extends the B2 preview endpoint with optional `source_id` dispatch. F7 lands the first concrete source (Spotify); F6 wires the dispatcher + mode-picker UI; F16 lands the og_tags parser to make `Source_Unknown` end-to-end.

1. **`Outpost_Source_Base` mirrors `Outpost_Companion_Base` inverted.** Class-level docblock cites the F1+F2 companion shape and lays out the parallel keys explicitly: `id` / `label` / `caveats` are shared; outbound has `detected` / `accepts_modes` / `accepts_media` / `max_attachments` / `alt_passthrough` / `char_limit` / `requires_auth`; inbound has `host_patterns` / `ambiguity` / `mode` / `mode_options` / `mode_default` / `extractor` / `recipe` / `mapping` / `h_entry_property` / `auth_required` / `tags_default`. Composer code can iterate either family with the same vocabulary.
2. **Extractors are dispatch types, not fetchers.** `Outpost_Source_Extractor_Base` declares `id()` / `expected_content_types()` / `compute_fetch_url()` / `parse()`. The B2 preview endpoint owns `wp_safe_remote_get` calls; extractors only declare WHICH URL B2 should fetch (recipe-driven for oEmbed, source-URL-verbatim for og_tags / mf2 / rss) and HOW to parse the response. No extractor calls a fetch primitive directly. Documented in `class-extractor-base.php` class docblock.
3. **URL-pattern matcher is bespoke string-comparison code, not regex.** Three accepted shapes: exact host (`open.spotify.com`), suffix wildcard (`*.example.social` — subdomains only, NOT the apex), exact host + path prefix (`boardgamegeek.com/boardgame/`). Plus `*` as the match-any sentinel for `Source_Unknown`. Validation runs at registration time via `Outpost_Source_Base::validate_pattern`, which rejects empty patterns, scheme prefixes, fragments, query strings, regex metacharacters (`[ ] ( ) ? + \ ^ $ | { }`), middle wildcards (`foo.*.example.com`), trailing wildcards (`example.*`), double wildcards, and path patterns missing the trailing slash. **DoS resistance** is the deciding factor: regex matchers paired with attacker-shared URLs can pin a CPU through pathological backtracking; suffix + exact + path-prefix has none of that surface.
4. **`Outpost_Source_Unknown` is the always-last fallback.** Registered lazily via `ensure_bootstrapped()` after the `outpost_sources_init` action fires (so concrete sources register first, then the registry appends Unknown). Capabilities: `host_patterns => ['*']`, `ambiguity => 'ambiguous'`, `mode_options => ['reply','like','repost','bookmark']`, `mode_default => 'bookmark'`, `extractor => 'og_tags'`, `mapping` keyed off `og:title` / `og:description` / `og:image`. Caveats array carries one i18n'd string explaining that no specific adapter detected the URL.
5. **`outpost_source_capabilities` filter is the public override point**, parallel to F2's `outpost_companion_capabilities`. Each `Source_*::capabilities()` applies the filter before returning so site owners can replace any key, restrict mode options, or extend caveats. Filter signature: `(?array $caps, string $source_id) => ?array`. Adapters fall back to their own constructed shape when the filter returns a non-array (defensive against buggy callbacks). Same pattern verified in F2 ActivityPub.
6. **Source_Unknown does NOT work end-to-end until F16.** Its declared extractor is `og_tags`, whose `parse()` is stubbed to throw `Outpost_Source_Extractor_Not_Implemented_Exception`. F5's preview endpoint mitigates by treating `Source_Unknown` matches identically to "no source matched" — falls through to the legacy `wp_safe_remote_get` + script-strip path that returns `{ html, finalUrl, contentType }`. Reply mode keeps working via the legacy path. F6's dispatcher must tolerate the throw equivalently. F16 makes Source_Unknown's extractor functional and the legacy fallback can retire then. **Acceptance criterion 7's "assert the throw" lands in the integration test stub** — the unit-level path returns the legacy shape rather than the exception, by design.
7. **B2 endpoint integration is additive, not replacing.** `Outpost_Preview_Endpoint::handle_request` gained an optional `source_id` parameter and a new dispatch branch. Three paths: (a) explicit `source_id` resolves to a registered non-Unknown source → extract via that source's recipe + extractor + mapping, return new `{ source_url, source_id, extracted, raw, warnings }` shape. (b) No `source_id` but `find_for_url` returns a non-Unknown source → same. (c) Source_Unknown matches OR no source registered → legacy `{ html, finalUrl, contentType }` path. SSRF defenses (wp_safe_remote_get's host-is-external filter chain), size cap, content-type validation, rate limit run BEFORE extractor parse in BOTH paths — the only thing extractor dispatch changes is which URL gets fetched (oEmbed templates the source URL into a recipe-declared endpoint) and which content-type prefixes are allowed (extractor-supplied vs the legacy text/html allowlist).
8. **`Outpost_Source_Extractor_Oembed` is the only concrete extractor in F5.** Six stubs (og_tags, mf2, rss, api_json, api_xml, composite) throw `Outpost_Source_Extractor_Not_Implemented_Exception`. The Oembed implementation: `compute_fetch_url` substitutes the source URL (rawurlencoded) into the recipe's `endpoint` template's `{url}` placeholder; refuses recipes without the placeholder (visible InvalidArgumentException) so silent endpoint reuse never happens. `parse` JSON-decodes; rejects oversized bodies (1 MB cap, defense-in-depth above the endpoint's 5 MB cap), rejects non-array decoded shapes, rejects JSON-list shapes (oEmbed responses are objects, not lists). Empty objects are accepted (the source's mapping handles missing fields).
9. **Naming divergences from prompt.** Repo conventions take precedence: `Source_Base` → `Outpost_Source_Base` (file `class-source-base.php`); `Source_Loader` → `Outpost_Source_Registry` (mirrors `Outpost_Companion_Registry`); `Source_Unknown` → `Outpost_Source_Unknown`. Tests in `tests/unit/` not `tests/sources/`. Exception class lives at `includes/sources/exceptions/class-extractor-not-implemented-exception.php`. Each divergence captured in this list so future Phase F prompts know what to expect.
10. **`do_action('outpost_sources_init')` fires from `ensure_bootstrapped()`.** Concrete sources subscribe to that action and register themselves; the registry then appends `Source_Unknown` so it's always last. Unit tests register sources directly (WP_Mock doesn't dispatch listeners for arbitrary actions); integration tests will exercise the production action-based wiring once wp-env lands.
