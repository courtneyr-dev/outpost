## Session F15 — Locked Decisions (shipped)

Closed 2026-05-04. Second concrete inbound source — YouTube. Validates F5+F6+F7 are correct end-to-end with a path-constrained source whose URL variants don't all fit the host-only host_patterns mechanism. Reuses Extractor_Oembed unchanged.

1. **F5 design gap surfaced: matches_url override is justified.** F5's `Source_Base::validate_pattern` accepts host-only patterns, suffix wildcards (`*.example.social`), and exact-host + path-prefix patterns (`boardgamegeek.com/boardgame/`) — but path-prefix patterns require a trailing `/`. YouTube watch URLs have path `/watch` (no trailing slash), so the host_patterns mechanism alone can't express "claim /watch but not /channel/". F15 declares host-only patterns AND overrides `matches_url()` to add the path constraint locally. Documented in the adapter docblock + test (`test_adapter_declares_only_capabilities_and_matches_url` — assertion is exactly two declared methods, not just one). **Follow-up filed**: extend Source_Base's pattern syntax to support trailing-slash-optional path prefixes (`youtube.com/watch?` or `youtube.com/watch$` to anchor without slash) so future sources with the same shape don't need an override. Until that lands, matches_url overrides are the established escape hatch.
2. **YouTube Music URLs route to Watch mode, NOT Listen.** Per Doc 2 §3.3: Listen mode is for audio-only platforms (Spotify, Last.fm, Snipd, future Pocket Casts). Music videos are still videos — the user shared a video URL, the composer should pre-fill Watch with the music-video metadata. Test enforces this: `test_mode_is_watch_for_youtube_music`. The decision is durable; flipping it would force Listen mode to handle video-bearing URLs which is an entirely different surface area.
3. **Path constraint: `/watch` exact OR `/shorts/<id>` prefix; youtu.be is all-paths.** PATH_CONSTRAINED_HOSTS = [youtube.com, www.youtube.com, m.youtube.com, music.youtube.com] — these all reject the homepage (`/`), channel URLs (`/channel/`, `/c/`, `/@handle`), playlist URLs (`/playlist`), feed URLs (`/feed/`). Only `/watch` and `/shorts/<non-empty>` succeed. youtu.be is the short-link host: any non-empty path matches (every youtu.be URL is a video). Bare `youtu.be/` (homepage redirect) does NOT match. Tests cover all 9 positive + 11 negative URL shapes.
4. **`/watch?v=X&list=Y` matches; pure `/playlist?list=X` does NOT.** The path-constraint walk only inspects path, not query — so `/watch?v=X&list=Y` is a watch URL that happens to also reference a playlist (treated as Watch). `/playlist?list=X` is path `/playlist`, which is NOT in the allowed list, so it routes to Source_Unknown (Bookmark default). Captures the user's intent: they shared a single video that's part of a playlist vs a playlist as a whole.
5. **Apex `youtube.com/watch?v=X` matches alongside `www.youtube.com`.** Some share-sheet variants (and Android intent EXTRA_TEXT in older Android versions) emit the apex form. Both are listed in PATH_CONSTRAINED_HOSTS. Test: `test_apex_youtube_com_watch_url_matches`.
6. **Mapping per Doc 2 §3.3.** title→p-name, thumbnail_url→u-photo, author_name→p-author (NEW vs Spotify, which doesn't expose author), provider_name→p-publication, @source_url→u-watch-of (always set, regardless of oEmbed success). Author is the YouTube channel name; `provider_name` is always literally "YouTube" — kept as p-publication for parallel-to-Spotify shape consistency even though it's redundant given the source_url already points at youtube.com.
7. **§5 audit gotcha: `@handle` URLs in fixtures fail B5.** YouTube oEmbed returns `author_url` in either `/@handle` or `/channel/UC...` form. The B5 lint scans `tests/fixtures/` for `@<token>` patterns and rejects anything outside the RFC-stock-name allowlist. Resolution: F15 fixtures use the `/channel/UC<placeholder>` form exclusively. Both forms are real YouTube responses; the channel form is what older accounts return and is the canonical permanent identifier (handles can be changed; channel IDs cannot). Captured here so future Source_* fixtures with platforms that emit `@handle` URLs (TikTok, Threads, Instagram) know to substitute the alternate identifier form rather than allowlist the handle. Same caution applies for any string `@token` patterns in fixture README files — `@group` references rewrote to `PHPUnit \`live\` group` to avoid the same B5 scanner.
8. **Fixtures use synthetic placeholder video IDs.** `EXAMPLE`, `SHORTS_EXAMPLE`, `MUSIC_EXAMPLE`, `HTML_ENTITIES_EXAMPLE`, `UTF8_EXAMPLE`. None resolve to real videos. Channel IDs are 19-char `UC<NAME>00...0` placeholders. UTF-8 fixture title (`公式チャンネル예시 동영상мира`) blends Japanese / Korean / Russian script to verify multi-byte flow without using a real video title. F8 #11 transparent-adapter contract enforced by `test_mapping_passes_html_entities_through_unchanged` and `test_mapping_preserves_utf8_multi_script_title` — the adapter passes raw bytes through; sanitization happens at composer-input / esc_html boundaries.
9. **No live test in F15.** F8 introduced the `@group live` pattern with Spotify; CLAUDE.md F8 #4 specifies live tests opt in via `@group live` annotation + `WP_TESTS_LIVE=1` env. F15 doesn't add a YouTube live test because the F8 prompt explicitly defers "live tests for sources beyond Spotify" to a later session that ships them as a batch. Fixture README documents the deferral (rerun `composer test:live` quarterly to catch contract drift; future session adds YouTube to the live group).
10. **Naming divergences from prompt.** Prompt: `Source_YouTube.php` under `includes/sources/in/`. Actual repo conventions: `includes/sources/class-source-youtube.php` with class `Outpost_Source_YouTube` (continues F5/F6/F7 convention; no `in/` subdir). Tests in `tests/unit/` not `tests/sources/`.
