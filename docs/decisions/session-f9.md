## Session F9 — Locked Decisions (shipped)

Closed 2026-05-04. Foundation of the manual cross-post adapter — the umbrella companion that registers manual-share targets for §5-impossible silos (Instagram, Facebook, X, LinkedIn, Threads, TikTok, Pinterest, Reddit, Flickr). F9 ships the declarative layer only; F10 lands Android intent firing, F11 iOS, F12 silo URL capture, F13 audit log surfacing.

1. **One umbrella companion, ten platforms.** `Outpost_Manual_Share_Adapter` extends `Outpost_Companion_Base` and contributes ten chips via a NEW method `platform_chips()`. Per-platform configs are declarative arrays (no per-platform PHP class) — quirks like `caption_via`, `ios_strategy`, `android_pkg`, `EXTRA_TEXT` honoring all live in config fields the F10/F11 intent-fire logic reads at runtime.
2. **Always-active without modifying the detector.** The umbrella's `file()` returns `OUTPOST_PLUGIN_BASENAME` so `Outpost_Companion_Detector::status()` reports `'active'` whenever Outpost itself is loaded. No detector changes needed; `is_active()` stays final on Companion_Base.
3. **`capabilities()` returns null; `platform_chips()` is the chip surface.** The umbrella itself is NOT a syndicate-to chip — returning null prevents `Outpost_Micropub_Bridges::merge_syndicate_chips()` from generating a meta-chip. Chips come from `platform_chips()` which the registry's `chips_for_mode()` enumerates alongside the F2 `capabilities()` chip via a new `collect_chips_from_adapter()` helper. `method_exists()` gates the platform_chips() call so the new contract is optional — feature-surface adapters keep working unchanged.
4. **`Outpost_Manual_Share_Platform_Config` validates strictly at construction.** Required keys (`id`, `label`, `icon`, `accepts_modes`, `caption_via`, `after_share`) MUST be present with correct types. Enum-typed fields (caption_via, after_share) reject unrecognized values. `id` MUST be kebab-case. Malformed configs throw `Outpost_Manual_Share_Invalid_Config_Exception` at registration time — a typo in a filter-registered platform surfaces during boot, NOT later when a user taps a chip.
5. **`prefers_bridgy` flag is strict-true only.** Only literal `true` enables Bridgy-defer for a platform. String "true", integer 1, etc. produce false. Defends against accidental enabling from misencoded filter values.
6. **`outpost_manual_share_platforms` filter is the documented extension point.** Site owners append/modify/remove platforms through this filter. Adding VSCO, Glass.photo, 500px, etc. is a one-call site-config change, no Outpost fork needed. CONTRIBUTING.md documents the shape with a Glass example. Tests demonstrate append, remove, and modify paths.
7. **Reddit-manual and Flickr-manual ship with `prefers_bridgy => true`.** A separate `outpost_manual_share_defer_to_bridgy` filter signals whether Bridgy Publish is configured; F14 will replace the default-false implementation with real `Companion_BridgyPublish::is_configured()` detection. Until F14, both chips remain visible because the defer filter returns false. The hide-when-Bridgy logic lives in `Outpost_Manual_Share_Adapter::platform_chips()` and is tested by mocking the defer filter to true.
8. **F9 ships photo/gallery chips only — text-only manual share is deferred.** The 10 platforms declare `accepts_modes => ['photo', 'gallery']` (TikTok adds video). X/Threads/Pinterest could in principle accept text-only Notes, but F9 scope is photo/gallery to validate the structure. Text-only manual share is a follow-up session; documented as deferred.
9. **REST endpoints under `/wp-json/outpost/v1/manual-share-*`.** `Outpost_Manual_Share_Controller` registers two routes:
   - `POST /manual-share/intent` — F9 stub returns `{status: stub, message, platform_id, post_id}` so the composer renders "intent firing not yet implemented (F10 Android / F11 iOS)" without requiring real intent logic.
   - `GET /manual-share-chips?mode=...` — Server-filters `chips_for_mode()` to entries carrying the `manual_share` extension key, so AP chips drop out and the composer's manual-share strip gets only manual platforms.
   Both routes share the syndicate-targets endpoint's auth posture: `show_in_index => false`, cookie/edit_posts/bearer permission, no SSRF surface. F9 prompt's "?q=manual-share-chips" Micropub query path didn't fit Outpost's "Shanske owns Micropub server semantics" architecture (per F1 #3) — REST mirrors syndicate-targets pattern instead.
10. **Naming divergences from prompt.** Prompt: `Companion_ManualShare.php`, `Platform_Config.php`, `Platform_Registry.php`, `Manual_Share_Controller.php`, `tests/companions/`. Actual repo conventions: `class-manual-share-adapter.php` with class `Outpost_Manual_Share_Adapter` (matches the `Outpost_*_Adapter` regex enforced by `Outpost_Companion_Registry::resolve_classes`); `includes/companions/manual-share/` subdir uses kebab-case; tests in `tests/unit/` with the existing pattern. Critical: the registry's class-name regex blocks adapters from outside the Outpost namespace — divergence from prompt's `Companion_ManualShare` was non-negotiable.
11. **WP_Mock `onFilter()->reply(false)` does NOT make `apply_filters` return false.** Discovered during F9 test development. Workaround: omit the filter mock entirely and rely on WP_Mock's default behavior (`apply_filters('hook', $default)` returns `$default` when no filter is registered). For tests that need `false`, do not mock the filter; only mock when you need a non-default reply (e.g. `true`). Captured here so F10+ tests against `outpost_manual_share_defer_to_bridgy` and similar boolean filters use the working pattern.
12. **Tests added: 33.** PHPUnit count 339 → 397 (with 9 new wp-env-pending integration stubs in `ManualShareIntegrationTest`). 16 new in `PlatformConfigTest` (required keys, enum validation, kebab-case id, defaults, prefers_bridgy strict-true, caveats/accepts_media filtering, full round-trip). 11 new in `PlatformRegistryTest` (10 default platforms, append/remove/modify via filter, malformed-throws, cache, Reddit+Flickr prefers_bridgy, all platforms accept photo or gallery). 12 new in `ManualShareAdapterTest` (file/label/feature_slugs/capabilities, platform_chips count, Bridgy-defer hides Reddit+Flickr, Companion_Registry::chips_for_mode integration, fail-open on unknown mode). 10 new in `ManualShareControllerTest` (intent stub success, invalid post_id/platform_id rejection, unknown platform error data, whitespace trimming, chips endpoint per-mode, listen mode empty, fail-open, no-mode all-chips). Existing CompanionRegistryTest updated: default-adapters count 7 → 8, chips_for_mode null count 1 → 11 (1 AP + 10 manual-share platforms).
