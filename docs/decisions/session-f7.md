## Session F7 — Locked Decisions (shipped)

Closed 2026-05-04. First concrete inbound source — Spotify. Validates F5+F6 are correct end-to-end with a real adapter.

1. **Source_Spotify validates F5's design with capabilities()-only implementation.** Adapter overrides nothing. Source_Base's defaults handle `matches_url` (host_patterns), `recipe_for_url` (verbatim recipe), `mode_for_url` (the unambiguous mode), and `map_extracted` (mapping with `@source_url` substitution). A reflection-based test asserts the only declared method on `Outpost_Source_Spotify` is `capabilities` — if a future change adds an override, the test fails loudly so the override gets justified in CLAUDE.md as a Source_Base design gap rather than smuggled through.
2. **oEmbed is the canonical extraction path; Web API is not used.** Spotify's Web API requires OAuth + (since Feb 2026) a Premium subscription. oEmbed at `https://open.spotify.com/oembed?url={url}` is anonymous, no API key, no advertised rate limit. §5-clean. Recipe declares `endpoint` template + `response_format: json`; F5's Extractor_Oembed handles substitution + parsing.
3. **Spotify URL variants handled.** `host_patterns` declares `open.spotify.com` (exact host) and `spotify.link` (exact host for short links). The host-only pattern claims every path: track, album, episode, show, playlist, intl-{lang} regional variants. Tests verify all 9 variant forms match. spotify.link short links rely on oEmbed following the redirect — verified in F7 live device test (acceptance #9).
4. **`/artist/` URLs match Spotify today, not Source_Unknown.** F5/F6's host-only patterns can't distinguish path within open.spotify.com. The user lands in Listen mode with empty p-name; can switch modes via the C0 mode-switcher. Future UX research may justify a `recipe_for_url` override that returns a different mode for `/artist/` paths — F5's template-method seam supports this without further design changes. Documented in adapter docblock + integration test stub (`artist_url_also_matches_spotify_pattern_today`).
5. **Mapping per concepts/capture-inbound-may-2026.md §3.1.** title→p-name, thumbnail_url→u-photo, provider_name→p-publication, @source_url→u-listen-of (always set, regardless of oEmbed success). The @source_url macro inside the mapping array is documented self-evidently; future readers see u-listen-of as part of the mapping shape rather than buried in the source's `h_entry_property` declaration.
6. **Degraded extraction paths produce a working composer.** D1 (404 / track deleted) → preview endpoint surfaces fetch_failed 502; composer falls back to manual entry. D2 (503 / Spotify down) → same. D3 (malformed JSON) → Extractor_Oembed::parse throws RuntimeException, preview surfaces 502. D4 (timeout) → wp_safe_remote_get returns WP_Error, preview surfaces 502. In every case u-listen-of is set client-side from the URL the user shared; only auto-fill of title / cover / publication is degraded. Tests cover D1 and D3 directly with offline fixtures; D2 and D4 share D1's code path (HTTP error handling) so don't need separate fixtures.
7. **Test fixtures use synthetic placeholder values, not a real track.** The fixture URL pattern (`/track/0000000000000000000000` — 22 zeros) is syntactically valid but doesn't resolve; tests mock the response body. Adapter code references zero specific tracks. §5 audit lint clean.
8. **Registration via `outpost_sources_init` action.** The hook fires from inside `Outpost_Source_Registry::ensure_bootstrapped` BEFORE the registry appends Source_Unknown, guaranteeing Spotify (concrete, exact-host) wins over Unknown (`*` fallback). Tests verify the order via direct registration + find_for_url assertions; the action firing is exercised in production boot, integration tests cover the wp-env-pending end-to-end run.
9. **Naming divergences from prompt.** `includes/sources/in/Source_Spotify.php` → `includes/sources/class-source-spotify.php` with class `Outpost_Source_Spotify` (continues F5/F6 convention; no `in/` subdir). Tests in `tests/unit/` not `tests/sources/`.
10. **Tests added: 35.** PHPUnit count 278 → 313. SourceSpotifyTest covers 26 paths: capabilities shape (3), URL pattern matching for 9 variants, 3 negative-pattern cases (non-Spotify URLs, Apple Music, accounts.spotify.com subdomain — exact-host doesn't match), mode_for_url across variants, mapping for track + album + episode fixtures, degraded D1 (404 body parses but mapping drops absent keys) and D3 (malformed JSON throws), oEmbed compute_fetch_url substitution, registry integration (find_for_url returns Spotify for Spotify URLs, Source_Unknown for others), filter override. Plus the reflection test asserting capabilities()-only. Integration test stub `SpotifyEndToEndTest` documents 9 wp-env-pending paths covering the full pipeline.
11. **§5 audit lint passes.** All 5 sub-checks clean. Adapter references no specific track / album / episode / playlist / handle.
12. **Live device verification deferred to one-time check.** Per acceptance #9, manually verify on Android that sharing a Spotify track to Outpost auto-routes to Listen mode with details pre-filled. NOT a CI requirement; documented in the F7 PR as the validation that share-sheet → composer-pre-fill works for real users.
