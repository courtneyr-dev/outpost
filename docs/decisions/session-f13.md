## Session F13 — Locked Decisions (shipped)

Closed 2026-05-04. Closes the ManualShare arc (F9–F13). Surfaces the audit log so users can see syndication status per post and act on incomplete entries: status badges, per-post detail view, reminder rollup with snooze + abandon UX. After F13 the manual-share subsystem is production-complete — F14+ moves to Bridgy Publish and remaining Source_* adapters.

1. **The audit log is the source of truth; status is derived on read.** Five states computed by `Status_Computer` from the entries array: `no_syndication` (empty log), `complete` (every entry has `completed_at`), `pending` (no completion), `partial` (mix of completion + pending), `abandoned` (every entry user-marked abandoned with no completion). Never stored — `compute_status_for_entries` is pure projection. Mixed pending+abandoned without completion stays `pending` so the user can still act.
2. **`reminder_dismissed_until` is per-entry, optional, ISO 8601 UTC.** F12 entries (no field) read with the field defaulted to `null`. Entries written with the field bump to schema version 2 in `update_entry`; v1 entries stay v1. Backwards-compatible — F10–F12 callers don't break.
3. **"Mark abandoned" = far-future timestamp sentinel (`2200-01-01T00:00:00+00:00`), not a separate boolean.** Single field carries both "snoozed for a week" and "permanently abandoned" semantics. The 10-year cutoff in `Status_Computer::is_abandoned()` distinguishes — anything past +10y is abandoned; shorter snoozes are still pending. Un-abandoning is via `Add URL anyway` clearing the field through the F12 capture endpoint.
4. **Snooze durations are PHP `DateInterval` shorthand (P1D / P3D / P7D) plus the literal `'forever'`.** Server-side `Reminder_Manager::resolve_until()` parses both. `'forever'` maps to `Audit_Log::ABANDONED_REMINDER_SENTINEL`. Defense-in-depth: arbitrary `strtotime`-able input also accepted but invalid input returns null so the controller rejects with 400.
5. **Snooze-all is rate-limited to once per ~5 minutes per user via WP transient.** Guards against accidental double-clicks snoozing weeks of pending state. The transient is per-user (keyed on user_id) so multiple users on the same site don't share rate-limit state. Tests cover happy-path + 429 rejection on second call.
6. **Color is never the only conveyance.** Status badges use Unicode glyphs (`✓` `⏳` `⚠` `—`) + visible text + `aria-label` with full state name. Glyph is `aria-hidden="true"` so screen readers don't double-read. Theme styles colors via the `outpost-syndication-badge--{status}` class but the badge works without color.
7. **Two surface layers: composer (Preact) + WP admin (PHP).** Composer surfaces: `SyndicationStatusBadge`, `SyndicationDetailView`, `ReminderRollup`, `SnoozeMenu`. Admin surfaces: posts-list "Syndication" column with sortable badges, F12 pending notice extended with badge + strategy info + "View detail" link pointing at the PWA composer. The admin "detail modal" deferred to keep admin-side JS-free; users follow the link to the PWA where the full detail view lives.
8. **`Pending_Capture_Detector` filtering — F13 visibility check.** Entries with `reminder_dismissed_until` in the future are dropped from prompt UX (composer + admin notice). Detail view still shows them — the filter is purely about prompt nag suppression. Abandoned entries (sentinel timestamp) get dropped too. Detector implementation: one-line addition calling `Reminder_Manager::is_snoozed()`.
9. **Per-status display text + aria-label tested across all five states.** `aria_label` covers every code path: "Syndication complete: N platforms", "Syndication partial: X of Y completed", "Syndication pending: N platforms", "Syndication abandoned: N platforms", "No syndication". Tests assert each label string appears in the rendered HTML, independent of the glyph or the theme color.

Also added docblocks to all REST handler methods in `Manual_Share_Status_Controller` since PHPStan flags untyped `$request` parameters. Captured here so F14+ controllers ship with full type docblocks from the start.
