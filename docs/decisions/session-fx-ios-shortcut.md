## Phase F parallel work — FX-iOS-Shortcut (shipped)

Closed 2026-05-04. Parallel session, NOT part of the F1→F16 main sequence. Unblocks iOS users for inbound share-target capture (Web Share Target API never landed in Safari per WebKit bug 194593). Android users continue to use Web Share Target Level 2 natively.

1. **Per-user long-lived token, scoped to one REST endpoint.** Token stored in user-meta `outpost_ios_shortcut_token`. Authenticates ONLY `/wp-json/outpost/v1/shortcut`; presented on any other REST route → 401. Scope enforcement is the load-bearing security boundary — a leaked Shortcut token must NOT escalate to full WP REST access (Micropub /media, IndieAuth, preview, etc.).
2. **NEW REST endpoint, NOT a migration of F6's `/post/shortcut`.** F6 ships `/post/shortcut` as a PWA route handled at `template_redirect` priority 1; that endpoint stays for cookie-authed users. FX adds `/wp-json/outpost/v1/shortcut` as the iOS-Shortcut-friendly contract: JSON in, JSON out, Bearer token auth via the standard WP REST authentication pipeline. The two coexist by design — `rest_authentication_errors` filter only fires on REST routes, so scope enforcement requires the REST surface.
3. **`Outpost_IOS_Shortcut_Token` is the storage / lifecycle layer.** Static-only. `regenerate(user_id)` issues + persists; `get_token(user_id)` reads; `revoke(user_id)` deletes. Regenerate ALSO clears the first-seen marker so settings page resets to "Not connected" until the next successful POST. Revoke clears both. Comparison uses `hash_equals` for constant-time defense-in-depth even though the underlying `meta_value` query already short-circuited on exact match.
4. **`set_resolver_for_tests( ?callable $resolver )` is the test seam.** Mirrors the F12 #9 pattern. Production uses `WP_User_Query` to look up users by token meta_value. Tests inject a static-array-backed resolver so they don't need to fake the WP_User_Query class via Mockery alias mocking. Pattern reusable for any future class that maps an opaque token to a user_id.
5. **`Outpost_IOS_Shortcut_Token_Authenticator` hooks `rest_authentication_errors`.** Decision tree:
   - No Bearer header → return null (passthrough; cookie / IndieAuth handle their own).
   - Bearer doesn't resolve to a Shortcut token → return null (let next filter try).
   - Bearer resolves AND request is for `/wp-json/outpost/v1/shortcut` → `wp_set_current_user`, record first-seen, return true.
   - Bearer resolves AND request is for any OTHER endpoint → return WP_Error 401 (`outpost_ios_shortcut_token_out_of_scope`).
   - Upstream filter already produced WP_Error or true → respect it (the `null !== $result` short-circuit at the top).
6. **Request URI is matched, NOT WP_REST_Request route.** `rest_authentication_errors` runs BEFORE `WP_REST_Server` resolves the route, so the request object's `route` property may not be populated. Inspect `$_SERVER['REQUEST_URI']` directly. Tolerate both `/wp-json/outpost/v1/shortcut` (pretty permalinks) and `/?rest_route=/outpost/v1/shortcut` (plain permalinks). REDIRECT_HTTP_AUTHORIZATION variant covered for Apache mod_rewrite installs that drop HTTP_AUTHORIZATION.
7. **`record_first_seen_if_unset` is idempotent.** First successful Shortcut POST sets `outpost_ios_shortcut_first_seen` to `gmdate('c')`. Subsequent successful POSTs do NOT overwrite — the timestamp tracks FIRST seen, not LAST seen. Settings page reads this to display "Connected." Last-seen tracking is a follow-up if needed; first-seen is sufficient signal for "this Shortcut is set up and working."
8. **Settings page lives at Settings → Outpost iOS Shortcut Bridge.** `manage_options` capability gate. On personal blogs (Outpost's primary surface) the admin IS the user; multi-user installs would surface this under Users → Profile in a future revision. Renders site URL + token + iCloud Shortcut link + connection status + regenerate / revoke forms. Uses standard WP admin styles (`.wrap`, `.form-table`, `.button`); no custom CSS — Hard Contract preserved.
9. **`assets/ios-shortcut-base-link.txt` ships as a placeholder.** The Shortcut is authored manually in the iOS Shortcuts app, exported once, and the public iCloud link captured. As of this commit the Shortcut is not yet published; the placeholder string starts with `PLACEHOLDER` so the settings page renders a "link coming soon" state instead of a broken link. `assets/ios-shortcut-base-link.README.md` documents the publishing flow. When the link is captured, replace the file contents and bump `OUTPOST_VERSION` per A2 #16 (user-observable settings page changes).
10. **`add_query_arg` test-bootstrap stub extended.** F1–F16 didn't exercise the array form `add_query_arg( array $params, string $url )`; FX's settings page redirect-after-POST does. Existing stub only handled the 3-arg form. Extended `tests/bootstrap.php` to also handle the array form, so the stub matches WP's documented signatures Outpost actually uses. Captured here so future code that calls `add_query_arg(array, url)` doesn't trip the same gap.
11. **`composer.json` PSR-4 + `phpunit.xml.dist` testsuite paths extended.** New test directories `tests/auth/` and `tests/admin/` added for FX. Mapped to `Outpost\Tests\Auth\` and `Outpost\Tests\Admin\` namespaces. PHPUnit's `unit` testsuite includes both directories so `composer test` covers them. Pattern reusable for future security-sensitive or admin-surface test directories.
12. **Tokens NEVER appear in test fixtures.** Per FX prompt's non-negotiable constraint. Test code uses synthetic tokens generated inline via the mocked `wp_generate_password` (which produces base64-derived placeholders). Lines that include synthetic tokens carry the F4 `outpost-lint:fixture-credential` suppression marker.
13. **`/post/shortcut` (F6) is not deprecated.** It still serves cookie-authed direct hits — useful for debugging the dispatcher in a regular browser without setting up a Shortcut. Both endpoints share the same `Outpost_Source_Detector::dispatch` logic; only the auth + response shape differ (303 redirect vs JSON `{redirect_url}`).
14. **No version bump.** FX ships REST endpoint + auth filter + admin settings page + test infrastructure. Nothing user-observable changes for non-iOS users; iOS users see the new settings page only after they look for it. The version bump comes when the iCloud Shortcut link is published (`assets/ios-shortcut-base-link.txt` updated from placeholder).
