## Session F16 — Locked Decisions (shipped)

Closed 2026-05-04. Concrete `Extractor_Og_Tags` parser + 8 OG-tag-driven inbound sources (Snipd, Twitch, Goodreads, LastFm, Readwise, Amazon, Pinterest, TikTok). Lifts the F5 #6 mitigation — Source_Unknown is now end-to-end functional via the og_tags parser, so any URL with OG tags gets best-effort metadata extraction in the composer.

1. **Parser does HTML entity decoding at parse time, NOT pass-through.** F8 #11's transparent-adapter contract for JSON-based extractors (Spotify, YouTube) doesn't apply to HTML-based extractors. JSON values are entity-decoded by the time `json_decode()` returns; HTML attribute values are byte-stream encoded (`&amp;`, `&#39;`, `&quot;`, `&hellip;`). Decoding at parse time is correct because that's where the byte stream stops being HTML. Source adapters then pass-through the decoded text per F8 #11. If the parser passed raw bytes through, every downstream consumer would have to re-decode and mistakes (double-decoding, missing entities) would propagate. Test enforced via `test_decodes_named_entities_in_content_values`, `test_decodes_html5_named_entities`, `test_decodes_numeric_character_references`. Decoding uses `html_entity_decode($value, ENT_QUOTES | ENT_HTML5, 'UTF-8')`.
2. **Regex parsing, NOT DOMDocument.** `<meta property="og:..." content="...">` tags are flat (no nesting, no inner text) and the failure modes are constrained: attribute order (`content` before `property`), quote style (single / double / unquoted), and `name=` instead of `property=`. All three covered. DOMDocument would also work but loads a heavier dependency and emits warnings on real-world malformed HTML. Outpost's existing CSS / HTML surfaces avoid DOMDocument for the same reasons.
3. **`extract_attr` walks capture groups by truthy index, NOT `??` chain.** PHPSubtle: `preg_match` populates unmatched alternation capture groups with empty strings (NOT unset entries). The `??` operator checks key-existence, not truthiness, so `$m[1] ?? $m[2] ?? $m[3]` returns the empty `$m[1]` and never falls through. Caught during F16 testing. Fix: explicit `foreach ( array(1,2,3) as $idx )` loop returning the first non-empty match. Captured here so future regex-with-alternation parsers (mf2, RSS, future XML extractors) don't repeat the bug.
4. **Multiple `og:image` tags collapse to first.** Some sites emit multiple `og:image` for different crops; Outpost's composer needs one canonical primary. First-wins is documented in `extract_og_properties` and tested via `test_multiple_og_image_collapses_to_first` against the edge-cases fixture which has two `og:image` tags.
5. **2 MB defense-in-depth size cap.** Above the preview endpoint's 5 MB cap. Real HTML pages with OG tags are well under 2 MB; anything larger is likely not a useful share target. Throws `RuntimeException` rather than returning an empty result so callers see the explicit failure mode. Test: `test_oversized_body_throws_runtime_exception` + `test_body_exactly_at_cap_passes`.
6. **Bulk path-constrained matchers, mostly via `matches_url` overrides.** Six of the eight F16 sources override `matches_url` to constrain to specific path prefixes (Snipd `/snip/`, `/episode/`, `/show/`; Goodreads `/book/show/`, `/review/show/`; LastFm `/music/`; Readwise `/highlights/`, `/bookreview/` + `/read/` on read.readwise.io; Amazon `/dp/`, `/gp/product/`; Pinterest `/pin/`; TikTok regex `^/@.+/video/.+`). Twitch is the only one that uses host-only matching (`twitch.tv`, `clips.twitch.tv`). Each override extends F15's design-gap follow-up — Source_Base path-prefix syntax requires trailing `/` which still doesn't fit any of these path patterns. Filed as the same follow-up; the override pattern is now established for the family.
7. **Amazon affiliate-tag stripping is the load-bearing privacy guarantee.** Amazon share-sheet URLs frequently carry `?tag=xxx-20` affiliate parameters that route earnings to the original sharer. Recording these on a personal blog leaks the third-party's commission relationship. Adapter strips a long list of known parameters (`tag`, `linkCode`, `linkId`, `ref`, `ascsubtag`, `pd_rd_w/r/wg`, `pf_rd_p/r`, etc.) before recording the URL as `u-bookmark-of`. `recipe_for_url` exposes the cleaned URL via a `canonical_url` field so the preview-endpoint integration can use it. Tests cover all known parameter classes individually + a "strips all known returns no query" assertion that the cleaning is complete.
8. **Last.fm mapping deliberately omits `og:description`.** Last.fm's track / album pages emit a Wikipedia-paste blob in `og:description` that produces awkward composer output. Adapter mapping omits the key entirely; tests assert `p-summary` is NOT in the mapped output. Future enhancement: intelligent description detection for artist pages (where the bio actually IS useful). Out of scope for F16 — the omission is the safe default.
9. **Readwise mapping routes `og:description` to `e-content`, NOT `p-summary`.** Per Doc 2 §3.8: the highlight text IS the post body, not a summary of it. Readwise is the only F16 source that uses `e-content` in the mapping. Outpost has no separate Quote mode in CLAUDE.md; Bookmark with `e-content` treatment is the closest fit. Test enforces this is the only `*-content` field set.
10. **§5 audit gotcha: `2768384` triggered B1.** Doc 2 §3.5's user-shelf URL contains `2768384-courtney-robertson` — the user's actual Goodreads ID. The opaque ID is on the F4 #3 narrowed B1 token list. The Goodreads test had `2768384-courtney` in a non-matching URL example; replaced with `0000000-example-user`. Lesson: when copying URL examples from research docs into test fixtures or test code, replace any opaque IDs with `0000000`-style placeholders. The research doc itself is exempt from B1 by filename — code and test files are not.
11. **§5 audit gotcha: `@example-creator` triggered B5 (TikTok fixture).** F15's `/channel/UC...` workaround doesn't work for TikTok because TikTok URLs MUST contain `@user` per the URL spec. Fixture uses `@alice` (RFC stock name from F4's fixture-handle allowlist). Test code can use `@example-creator` because the B5 lint only scans `tests/fixtures/`, not `tests/unit/`. Documented in TikTok README so future Source_* fixtures with `@handle`-emitting platforms (Threads, Instagram, Mastodon when its turn comes) know which pattern fits which scope.
12. **`Source_Unknown` end-to-end mitigation lifts.** F5 #6 noted that Source_Unknown declared `extractor='og_tags'` but the parser was stubbed; preview endpoint preserved a legacy code path on Source_Unknown matches. F16's concrete parser makes Source_Unknown end-to-end functional — any URL with OG tags gets `p-name` from `og:title`, `p-summary` from `og:description`, `u-photo` from `og:image`. The F5 mitigation can retire when callers transition to the structured shape; until then both paths coexist. Updated docblock + new test `test_end_to_end_parser_plus_mapping_with_concrete_og_extractor`.
13. **Naming divergences from prompt.** Per F5–F15 conventions: `Source_Snipd.php` → `includes/sources/class-source-snipd.php` with class `Outpost_Source_Snipd`; same shape for Twitch, Goodreads, LastFm, Readwise, Amazon, Pinterest, TikTok. Tests in `tests/unit/`. Adapters use `final` + `declare(strict_types=1)`.
