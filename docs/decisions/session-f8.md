## Session F8 — Locked Decisions (shipped)

Closed 2026-05-04. Two-part deliverable: hardened Source_Spotify coverage (Part A) and the offline fixture pattern formalized for every later `Source_*` (Part B). Pattern lives at `tests/fixtures/sources/{source_id}/{scenario}.{ext}`; F15+ inherits.

1. **Fixture directory convention is locked: `tests/fixtures/sources/{source_id}/{scenario}.{ext}`.** Every Phase F `Source_*` adapter ships fixtures under its own subdirectory keyed off the source's id (`spotify`, future `youtube`, `vimeo`, etc.). Each subdirectory has a `README.md` populated from `tests/fixtures/sources/_TEMPLATE_README.md` (capture date, source URL, sanitization, last-verified-live date). F7's five fixtures migrated from `tests/fixtures/spotify-*.json` to `tests/fixtures/sources/spotify/oembed-*.json` and renamed (no `spotify-` prefix — it's redundant inside the source's directory).
2. **`SourceFixtureLoader` and `MockHttpClient` live under `Outpost\Tests\Helpers\`.** New autoload-dev PSR-4 mapping `tests/helpers/` → `Outpost\Tests\Helpers\`. Loader exposes `load_oembed_fixture()`, `load_html_fixture()`, `load_json_fixture()`, and `load_raw_fixture()` (raw is for tests that want unparsed bodies — malformed JSON, non-JSON 503 fixtures). Missing fixtures throw with the path in the message so the failure names what's missing rather than producing a confusing "json_decode returned null" downstream.
3. **MockHttpClient is a test-layer fixture-driven response builder, not a production injection seam.** F8's prompt asked for `Extractor_Oembed::set_http_client()`, but F5's design has Extractor_Oembed only doing `compute_fetch_url()` and `parse()` — the HTTP fetch lives in `Outpost_Preview_Endpoint::handle_request`. Adding a setter to Extractor_Oembed would be dead code. Net: MockHttpClient produces `wp_safe_remote_get`-shaped response arrays; integration tests that exercise the preview-endpoint pipeline (currently wp-env-pending) wire it via `WP_Mock::userFunction('wp_safe_remote_get')->andReturnUsing(...)`. Unit tests for `Extractor_Oembed::parse()` and `Source_Spotify::map_extracted()` work directly off `SourceFixtureLoader::load_oembed_fixture()` — there's no HTTP layer to mock.
4. **Live tests use `@group live` class annotation + `WP_TESTS_LIVE=1` setUp guard (defense-in-depth).** Two layers of skip: phpunit.xml.dist's `<groups><exclude>live</exclude></groups>` excludes the group from the default suite (tests don't even load), AND `setUp()` checks the env var and `markTestSkipped()`s if missing. Either layer alone would protect CI; both means a maintainer can opt into running live tests via `--group=live` alone (rare) without leaking them into the default. `composer test:live` runs `WP_TESTS_LIVE=1 phpunit --group=live` — sets both gates green at once.
5. **Live test annotation MUST attach directly to the class, not to the file-level docblock.** PHPUnit 9.6 doesn't pick up class-level `@group` from the first docblock in a file (which it treats as the file docblock). The annotation needs its own docblock immediately above `final class SourceSpotifyLiveTest extends TestCase`. Captured here so future Source_*LiveTest files follow the working pattern from the start.
6. **Live tests use PHP-native `file_get_contents` + stream context, NOT `wp_safe_remote_get`.** The unit-test bootstrap doesn't load WordPress core, so wp_safe_remote_get is unavailable. Live tests verify the third-party API contract (response shape); the preview-endpoint integration (SSRF defenses, content-type validation, size cap, rate limit) is covered by wp-env integration tests. The two layers test different things: API contract vs request-handling.
7. **Live tests skip on network failure, do not fail.** `file_get_contents()` returns false on connection failure; the test calls `markTestSkipped()` rather than `fail()`. Reasoning: a developer on an airplane shouldn't have `composer test:live` fail when their network is down — it should report "couldn't reach Spotify, try again" not "Spotify is broken." Real contract drift produces a different failure (assertion mismatch on the parsed response), distinguishable from network unavailability.
8. **Default live target URL is configurable via `OUTPOST_TEST_<SOURCE>_URL` env var.** `SourceSpotifyLiveTest` defaults to a durable Daft Punk track URL (on Spotify since launch, widely distributed); the env override is the maintenance path when that resource ever moves. Future `Source_*LiveTest` files follow the same env-var convention.
9. **§5 audit lint already covers `tests/fixtures/sources/` recursively.** B1's path scope is `tests/`; B5's path scope is `tests/fixtures/`. Both are `grep -r` scopes, so the new subdirectory is scanned without lint changes. F8 commit doesn't extend the lint; documenting here so a future Phase F session knows the lint reach is "everything under tests/" — adding fixtures elsewhere would require extending the lint.
10. **Spotify fixture set: 17 files.** 5 happy paths (track, album, episode, show, playlist) + 12 edge cases (no-thumbnail, html-entities, utf8-korean, utf8-arabic, utf8-cyrillic, script-injection, javascript-url, empty-title, very-long-title, 404 error body, 503 non-JSON HTML, malformed JSON). UTF-8 fixtures use public-domain folk songs (아리랑 Korean, موسيقى الكلاسيكية Arabic generic phrase, Калинка Russian) — real non-ASCII content rather than `lorem ipsum`, which proves UTF-8 actually flows through, but not personal data. Synthetic 22-zero placeholder track ID convention from F7 preserved across all fixtures.
11. **Adapter contract reaffirmed: data-shape declarative, NOT sanitizing/decoding/truncating.** Part A's defensive tests (script tags, javascript: URLs, file:// URLs, zero-width unicode in provider name) all assert the adapter passes the raw value through. Sanitization lives at the layer that needs it: preview endpoint strips scripts in HTML responses; composer pre-fill assigns to `<input value>` via DOM (browser handles entity decoding); render-time `esc_url()` rejects non-http(s) schemes. Doing it in the adapter would silently transform user-visible data and double-encode anything Spotify already decoded. The transparent-adapter contract is now test-enforced.
12. **Tests added: 28.** PHPUnit count 313 → 339 (excluding 2 live tests skipped from default suite). 26 new in `SourceSpotifyExpandedTest`: 8 A1 (extra fields, html entities, korean, arabic, cyrillic, very-long, scdn, no-thumbnail) + 4 A2 (script, javascript-url, file-url, zero-width unicode) + 6 A3 (si tracking, fragment, intl+query, no-trailing, trailing-slash, fetch_url query preservation) + 8 A4 (all-missing, null-treated-as-missing, empty-string, show, playlist, 503, null-provider, listen-of-always). 2 new in `SourceSpotifyLiveTest` (oembed contract, mapping h-entry shape). F7's 26 unit tests refactored to use `SourceFixtureLoader` — assertion count preserved.
13. **No version bump.** F8 ships test infrastructure + fixtures; no production-code change ships to users. CLAUDE.md's A2 #16 rule (any deployable behavior change moves the version) doesn't trigger.
