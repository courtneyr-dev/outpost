## Session F10 — Locked Decisions (shipped)

Closed 2026-05-04. Replaces F9's stub for the Android branch with real intent firing: pre-stage media, write clipboard, fire `navigator.share()` with files, fall back to intent:// URL when needed. iOS still routes to the F9 stub until F11. Audit-log scaffold writes entries on chip-tap (F12 will extend with completion-tracking; F13 surfaces).

1. **Platform config drives behavior; no platform-name branches in code.** `Outpost_Manual_Share_Intent_Payload_Builder` reads `Platform_Config::to_array()` for `android_action`, `android_pkg`, `android_mime`, `android_extras`, `web_intent_url`, `caption_via`, `after_share`. Quirks like Facebook ignoring `EXTRA_TEXT` or TikTok using `com.zhiliaoapp.musically` are config values, not if-statements. F9's platform configs were deliberately rich enough that F10 needed zero per-platform code paths.
2. **navigator.share preferred; intent:// URL fallback; two-tap worst case.** PWA-side `execute_android_share` is a deterministic fallback chain — clipboard always writes first, then native share with files, then `window.location.href = fallback_url`, then a structured `'aborted'` two-tap result if no path is viable. Telemetry posts on every outcome.
3. **Web intent URL is iOS-only on F10's reading; Android falls through to intent://.** When a platform declares `caption_via='intent'` (X, LinkedIn, Pinterest) AND `web_intent_url` is set, F10's `build_fallback_url()` deliberately ignores the web intent on Android — the intent:// URL is the better path because Android honors EXTRA_TEXT and the web intent doesn't accept image attachment. F11 will route iOS to the web intent URL where it's the only viable path. Captured here so F11's iOS branch knows to consult `caption_via` + `web_intent_url` together.
4. **`caption_via='web_intent'` is the explicit primary-web-intent signal.** Threads, Reddit-manual, Flickr-manual declare this; their strategy is `intent_url` (PWA navigates straight to the web URL, skipping `navigator.share`). Pinterest/X declare `caption_via='intent'` because Android EXTRA_TEXT works — strategy stays `navigator_share` with intent:// as fallback. The two cases ARE different; F9's configs encode the distinction.
5. **EXTRA_STREAM/EXTRA_TEXT short names expand to canonical Android extras.** F9 platform configs use short names (`EXTRA_STREAM`, `EXTRA_TEXT`); the intent:// URL builder maps them to `android.intent.extra.STREAM` / `android.intent.extra.TEXT` because Android target apps look up by the canonical name. Unknown short names pass through verbatim so future platform-specific extras (Instagram Stories' `interactive_asset_uri`) work without map updates.
6. **Audit log writes on intent fire with outcome='unknown'; PWA telemetry updates with real outcome.** `Outpost_Manual_Share_Audit_Log::add_entry()` runs from the payload builder during the POST `/manual-share/intent` request and returns the entry id in the response. The PWA fires `POST /manual-share/intent/log` with `{post_id, audit_log_id, outcome}` after the share resolves; the controller's `handle_log_request` patches `outcome` via `update_entry`. Net effect: even if the PWA crashes before telemetry, the audit log records the firing attempt.
7. **`outpost_manual_share_log` post-meta is the single storage location.** Per-post layout means a single post's share history is one query; cross-post analytics is a future concern (Phase H+). Auto-cleans on post deletion, integrates with WP backup/export tooling.
8. **Per-post `current_user_can('edit_post', $post_id)` check inside `handle_request`.** Acceptance criterion #10: cross-user post_id rejected with 403. Bearer-token auth via the IndieAuth plugin sets the current user before this check; the per-post cap then applies. The endpoint's `permission_callback` still runs first (cookie/edit_posts/bearer presence — coarse-grained); the per-post check is the second layer.
9. **WP_Post stub added to tests/bootstrap.php.** F10's `Intent_Payload_Builder` does `instanceof WP_Post` checks for type safety. The unit-test bootstrap previously only stubbed `WP_Error`, `WP_REST_Request`, `WP_REST_Response`, `WP_Term`. F10 added `WP_Post` to the same pattern so future tests touching post objects work without per-test stub gymnastics.
10. **WP_Mock function-mock re-registration is brittle; use class-property dispatch.** Discovered during F10 test development. Re-registering `WP_Mock::userFunction('foo')` mid-test produces unpredictable behavior (the new registration may layer over rather than replace the setUp default). Reliable pattern: setUp registers a closure that consults a class property (e.g. `$this->meta_store`, `$this->user_can_edit_post`); individual tests flip the property to change behavior. Captured for F11+ tests against `current_user_can` / `get_post` / similar.
11. **`@image_uri` is a runtime placeholder filled by the PWA.** The server's intent:// URL contains `%40image_uri` (the URL-encoded form because it lives in a query parameter). The PWA's `fill_intent_url()` substitutes BOTH the raw `@image_uri` token and the percent-encoded `%40image_uri` form. Practical reality: `@image_uri` substitutes to a `blob:` URL (the only file-URL the PWA can construct), which Android target apps generally don't accept in `EXTRA_STREAM`. The intent:// URL fallback is therefore most useful for caption-only platforms; image-bearing intents rely on `navigator.share()` directly.
12. **PWA tests inject deterministic environments — no real navigator/clipboard/fetch touched.** `AndroidShareEnvironment` carries the four primitives (`navigator_share`, `navigator_can_share`, `clipboard_write_text`, `fetch`) plus `navigate` (window.location.href setter) and `post_telemetry` (the audit-log POST). `default_environment()` builds from globals for production; tests pass synthetic environments. 33 Vitest tests cover happy path + every fallback branch + clipboard resilience + telemetry resilience.
13. **PWA composer chip-strip rendering UI is deferred.** F10 ships server payload + PWA modules; the actual composer-side "tap chip → execute_android_share" wiring is a separate concern that lands when both Android (F10) AND iOS (F11) handlers exist, so the strip can route by platform without re-rendering. F11 will land iOS handler + the unified composer integration. Documented as F10's deferred follow-up rather than a missed acceptance criterion.
