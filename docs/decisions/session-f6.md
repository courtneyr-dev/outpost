## Session F6 — Locked Decisions (shipped)

Closed 2026-05-04. Share-target dispatcher. Server-side decides what composer route a shared URL maps to (auto vs picker), 303-redirects to the composer with the appropriate query params. F6 ships against Source_Unknown only (the F5 default) — the dispatcher mechanism works without any concrete source registered. F7 ships Source_Spotify and verifies the dispatcher is correct end-to-end.

1. **Dispatch is stateless; redirect-based handoff.** `Outpost_Source_Detector::dispatch( $url, $context )` is a pure function over the URL + currently-registered sources. Returns a route-decision array `{ route_type, mode|mode_options, source_id, redirect_url, prefill_token? }`. The HTTP 303 redirect is the entire handoff between server-side dispatch and client-side composer rendering — no session storage, no transient between requests. Composer reads its query params; that's it.
2. **URL extraction priority chain.** Different platforms put the URL in different fields. The chain: (1) `url` field if it's a valid http(s) URL, (2) `text` field starting with http(s)://, (3) `text` field containing an http(s) URL anywhere (regex-extracted, validated via wp_parse_url), (4) `title` field starting with http(s)://. Returns null when no URL is detected — caller routes to the share-text-only flow (Note mode with title/text pre-filled, no source URL). Implemented in `Outpost_Source_Detector::extract_url_from_payload`.
3. **iOS Shortcut bridge endpoint at `/post/shortcut` accepts JSON.** Web Share Target API never landed in iOS Safari (WebKit bug 194593, still open as of May 2026). The iOS Shortcut bridge POSTs `{ url, shared_text? }` to this alias endpoint. Same dispatcher under the hood; just JSON in / 303 redirect out. The Shortcut .plist generation is a separate session (Phase E or later) — F6 ships only the receiving endpoint so the Shortcut author has a fixed contract.
4. **Pre-fill preview is a fire-and-forget transient.** For unambiguous (auto) routes, `Outpost_Share_Target_Controller::enqueue_preview_transient` writes a per-user, per-URL-hash transient marker before the redirect issues. The composer reads the cache slot via the existing `/preview` endpoint on mount; cache miss falls back to a fresh preview fetch. The transient is an optimization, not a dependency. TTL 5 minutes (long enough for the redirect roundtrip; short enough not to bloat the DB). Ambiguous (picker) routes do NOT enqueue — the user picks mode first, since different modes may want different recipes (Reply wants citation context; Bookmark only wants the URL).
5. **Source_Unknown is the universal fallback; F6 tests it as the only-registered-source baseline.** Every URL dispatches to mode-picker with Bookmark default when only Source_Unknown is registered. This is the F5 default state — F6 verifies the dispatcher works end-to-end without depending on any concrete source.
6. **No platform branching in dispatch logic.** `$context['platform']` exists for telemetry only — never branches dispatch. Behavior is identical regardless of whether the request came from the Android share sheet, the iOS Shortcut bridge, or a desktop bookmarklet. Keeps dispatch deterministic and reproducible. Documented in `Outpost_Source_Detector::dispatch` via an explicit `unset( $context )` after the function signature.
7. **Bespoke URL-pattern matcher inherits F5's "registration order is priority" rule.** F6's "exact host beats wildcard" test confirms the contract: source authors register exact-match patterns BEFORE wildcards, and the first match wins. Documented explicitly in the F6 test docblock so future Phase F sessions don't expect different ordering semantics.
8. **Layered SSRF defense.** Dispatch is pure URL → redirect, doesn't fetch. SSRF guards live at the F5 preview endpoint via `wp_safe_remote_get`'s `http_request_host_is_external` filter chain. F6 dispatch can build a redirect URL pointing the composer at a localhost URL; the eventual B2 fetch rejects per F5's defenses. Test verifies both layers separately (dispatch builds redirect for localhost; B2 blocks fetch). Composer cannot bypass either layer.
9. **`Outpost_PWA_Shell::halt()` is now public** so F6's controllers can halt the request after issuing redirects without duplicating the testing-define seam. Same exit semantics as before — `OUTPOST_TESTING_PWA_SHELL` define skips the actual `exit` so unit tests work.
10. **PWA-side glue is minimal: `parse_dispatch_params` extends `share-target.ts`.** Reads F6-specific query params (`mode` / `picker` / `default` / `source` / `cached_for` / `url` / `text` / `title`) and emits the existing `ShareTargetData` shape so the composer's existing mode-mount logic (`ComposerTabs` + per-mode `consume_share_target_for_*`) picks up the data without changes. Composer entry in `index.tsx` calls the new parser on `/post/` route mount, stashes if non-null, and strips query params via `history.replaceState` so refresh doesn't re-stash. Bundle: +0.17 KB gzipped (33.52 → 33.69, 84% of Phase C budget).
