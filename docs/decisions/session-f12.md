## Session F12 — Locked Decisions (shipped)

Closed 2026-05-04. Closes the manual-share two-phase loop: when the user returns to Outpost after posting in a destination app, they paste the silo URL into a small inline prompt, Outpost writes a `u-syndication` link to the post's microformats output. Bridgy and other webmention consumers parse the marker to find the silo copy.

1. **Phase-2 capture is non-blocking.** The prompt is a soft nudge — users can ignore it indefinitely; the post stays valid. The detector hides entries past a 30-day retention window so abandoned shares don't accumulate, and within a 30-second grace period after firing so the prompt doesn't appear during the share itself.
2. **URL validation is liberal.** Accept any http/https URL of any domain (custom domains, archived posts, future silos). Reject empty / whitespace, non-http schemes (file://, javascript:, data:), URLs that fail `wp_http_validate_url` (rejects loopback + RFC 1918 + link-local). Length cap 2048 chars.
3. **No silo scraping.** Outpost does NOT fetch the pasted URL to verify it. That would add complexity, fail unpredictably (silos block logged-out fetchers), and not improve the IndieWeb plumbing. Trust the user to paste what they meant.
4. **Soft-warn on platform mismatch.** When the URL's domain doesn't match the platform_id's expected domain (Instagram chip + Twitter URL), the controller returns `status: 'mismatch_warning'` instead of recording. The PWA shows a confirm prompt; user clicks "Save anyway" → resubmits with `confirm_mismatch: true`. Unknown platforms (custom site-registered) skip the mismatch check entirely.
5. **Storage shape: `outpost_syndication_links` post-meta is canonical.** Array of `{platform_id, url, added_at, source}` per entry. Idempotent: writing the same `(platform_id, url)` pair twice updates `added_at` rather than appending. The renderer derives HTML from this meta — meta is the source of truth, not the rendered HTML.
6. **`u-syndication` rendered hidden by default.** The renderer wraps anchors in `<div class="outpost-syndication-links" hidden>` so mf2 parsers see them in the source HTML but visible content stays clean. Themes wanting to show the syndication links override `[hidden]` in CSS or use `outpost_render_syndication_links` filter for full programmatic control. The_excerpt also includes the wrapper so Bridgy's feed-scanning paths work.
7. **Two surfaces: composer panel + WP admin notice.** PWA's `PendingSyndicationsPanel` lists pending entries with inline `SyndicationCaptureForm` (URL input + Save/Cancel + mismatch confirm). WP admin's `Outpost_Pending_Syndication_Notice` appears on post-edit screens listing pending entries, points users at the PWA composer for the inline form (avoids shipping admin-side JS just for the form).
8. **`register_post_meta` exposes `outpost_syndication_links` via WP REST.** Tools that read post objects via `/wp-json/wp/v2/posts/N` get the syndication state programmatically. `auth_callback` requires `edit_posts` cap so the meta only surfaces to authenticated callers (defense-in-depth; the array contains URLs the user posted, not credentials, but consistent with the rest of Outpost's posture).
9. **`Pending_Capture_Detector` accepts a candidate-resolver injection for tests.** Production uses WP_Query with `meta_query` for posts that have the `outpost_manual_share_log` meta key. Unit tests inject a static array of post IDs to bypass WP_Query — simpler than mocking the WP_Query class. Captured here so future detectors that scan post-meta follow the same test seam pattern.
10. **`DAY_IN_SECONDS` / `MINUTE_IN_SECONDS` / `HOUR_IN_SECONDS` defined in tests/bootstrap.php.** F12's detector uses `DAY_IN_SECONDS * $retention_days`. The constants come from WordPress core but the unit-test bootstrap doesn't load core. Added the three time constants to the bootstrap stub; future Phase F+G detectors that use WP time constants benefit.
11. **Webmention triggering on writeback deferred.** F12 prompt mentions sending a webmention to the silo URL on writeback (Pfefferle Webmention plugin pattern). Outpost has no existing webmention sender — there's no F-earlier infrastructure to extend. Documented as a follow-up to F12 / Phase G concern when webmention sender lands.
12. **PWA composer integration deferred (consistent with F10 #13 / F11 #11).** F12 ships the panel + form components + capture-api helper as testable building blocks. Mounting `PendingSyndicationsPanel` in the composer's main view is a separate concern — the natural integration point is when F13 (audit log surfacing) lands and the composer needs to manage all three surfaces (chip strip, pending panel, audit log) together. Tests cover each component in isolation; production integration is a focused follow-up.
13. **Naming divergences from prompt.** Prompt: `Syndication_Writeback.php`, `Pending_Capture_Detector.php`, `Syndication_Capture_Controller.php`, `Pending_Syndication_Notice.php`, `Syndication_Links_Renderer.php`, `tests/companions/manual_share/Syndication_WritebackTest.php`. Actual repo conventions: `class-syndication-writeback.php` (lowercase + dashes); REST controller at `includes/class-syndication-capture-controller.php` (top-level); admin notice + renderer at `includes/class-pending-syndication-notice.php` + `includes/class-syndication-links-renderer.php`; tests in `tests/unit/`. Continues F9–F11 pattern.
14. **Tests added: 51 PHP + 27 PWA = 78.** PHP 456 → 513 (with 6 wp-env-pending integration stubs in `SyndicationCaptureFlowTest`): `SyndicationWritebackTest` 22, `PendingCaptureDetectorTest` 13, `SyndicationCaptureControllerTest` 9, `SyndicationLinksRendererTest` 7. PWA 251 → 278: `capture-api.test.ts` 11, `syndication-capture-form.test.tsx` 7, `pending-syndications-panel.test.tsx` 9. All gates green: PHPCS, PHPStan, §5 audit, PHPUnit, Vitest, TypeScript strict.
15. **No version bump.** F12 ships server-side endpoints + post-meta registration + the_content filter + admin notice + PWA components. The user-observable change ships when the composer integration mounts the panel; F12 is the foundation F13+ wires in.
