## Phase F parallel work — FY-Theming (shipped)

Closed 2026-05-04. Parallel session, shipped as three stacked PRs: PR(a) Token_Resolver + Theme_Json_Reader + Contrast + Mode_Controller; PR(b) Settings UI + REST + sandboxed live preview; PR(c) Field Notes treatments + SVGs + B6 lint. Theme inheritance lets a site's block-theme palette + fontFamilies flow into the composer; per-user appearance overrides layer on top; day/night/system mode controls per-user. Hard Contract preserved: plugin owns layout, theme owns paint; the resolver only EMITS token values, never bypasses the contract.

### PR(a) — resolver foundation

1. **Four classes, one resolver path.** `Outpost_Token_Resolver` is the orchestrator; `Outpost_Theme_Json_Reader` reads palette + fontFamilies from the active block theme's `theme.json` (handles v2 single-palette + v3+ style variations); `Outpost_Contrast` does WCAG 2.1 ratio + adjust-for-minimum walk in HSL space; `Outpost_Mode_Controller` reads/writes per-user appearance mode (defaults `'system'`).
2. **Priority chain: override → theme → default.** Resolver walks the chain per-token. Override wins, falls back to theme, falls back to FY default (warm-paper Field Notes neutrals — CC0 values, not attributable to any specific user's site).
3. **Slug priority lists for theme.json mapping.** text → `foreground/primary/ink`; bg → `background/surface/paper`; accent → `accent/primary/brand`; accent_2 → `secondary/accent-2/accent-secondary`. Fonts: body → `body/primary/sans`; display → `display/heading/headings/secondary/serif`; monospace → `monospace/mono/code`. First-match-wins per priority list.
4. **Variation slug substring match.** `'dark-pro'` style variation registers as the night-mode theme palette. Substring (`stripos`) lets variations named `Dark Pro`, `dark-pro`, `pro-dark` all resolve to night.
5. **Contrast enforcement is per-token, not global.** text/text_secondary checked against surface for AA body (4.5:1); accent against surface for AA large (3.0:1). `bypass_contrast` is a per-token escape hatch on the override storage, not a global disable. The resolver returns an `adjusted` array naming any tokens whose effective value moved due to enforcement.
6. **Adjust-for-minimum walks HSL lightness 1% steps biased away from background luminance.** Preserves design intent: a dark primary on white stays dark, just darker. Bias direction picked by which side of the bg luminance the foreground starts on.
7. **Transient cache keyed on (user_id, mode, theme_version).** Theme switch implicitly invalidates because theme version changes. Per-user means a multi-author site doesn't fight cache between users.
8. **`set_reader_for_tests()` test seam mirrors F12 #9 / FX #4 pattern.** Production uses real `WP_Theme_JSON_Resolver`; tests inject deterministic readers without touching globals.
9. **Per-user storage for both mode AND overrides.** `outpost_appearance_mode` + `outpost_appearance_overrides` user-meta keys. Site-options would prevent the multi-author personalization the prompt asks for; user-meta is the only fit.
10. **`to_css()` emits a `.outpost-mode-{mode}` block with token-only declarations.** Passes B6 by construction (the only hexes are inside the value of `--outpost-*` declarations, which are token declarations themselves and not subject to B6's component-CSS scope).

### PR(b) — settings UI + REST + live preview

11. **REST endpoints under `/wp-json/outpost/v1/appearance/tokens`.** GET returns the resolved token payload; POST accepts override + mode updates. Both `edit_posts`-gated; `show_in_index => false`.
12. **Strict validation on submitted values.** Color: hex (3/6/8 chars), rgba(), or safe-named-allowlist (transparent, currentcolor, black, white, named primaries). Font: shape check (rejects `\r\n` + `;{}<>\``). Token slug: kebab/snake_case max 32 chars.
13. **Synthetic `WP_REST_Request` forwarding from admin-post.php.** The settings page's form posts to admin-post.php → builds a synthetic `WP_REST_Request` → calls `Outpost_Appearance_REST_Controller::handle_post()` directly. Single write path: validation, persistence, cache invalidation all live in the REST controller; admin-post.php is just an alternate entry point. Avoids duplicating logic between admin form and REST.
14. **Empty `mode_preference` means "no change requested".** Initial bug: empty mode triggered 400 because the validator rejected unknown modes. Fix: `if ('' !== $mode_value)` guard treats empty as no-op so settings-page POSTs that don't touch mode (e.g., just override edits) don't get rejected.
15. **Empty token value clears that token.** Setting an override to `''` removes the entry from the user's overrides array — equivalent to "revert to fallback chain (theme → default)."
16. **Live preview iframe via srcdoc + `sandbox="allow-same-origin"`.** Self-contained `<!doctype html>...</html>` injected as srcdoc. PWA-side ~50-line vanilla JS rebuilds inline `<style id="outpost-preview-tokens">` textContent on input/change events. Style isolation without routing coupling — preview can't navigate, can't run script outside its sandbox.
17. **Six subset components in preview.** Tab bar (3 tabs), section heading, form input, radio group, primary button, voice icon (🎤). Enough to read the aesthetic; not so much that the preview is the whole app.
18. **`bootstrap.php` extended `WP_REST_Request` stub** with `set_header/get_header/set_body/get_body/get_json_params/get_body_params` so synthetic requests work in unit tests.
19. **`SAFE_NAMED_COLORS` allowlist intentionally narrow.** transparent, currentcolor, black, white, red, green, blue, yellow, orange, purple, gray, grey. Rejects everything else CSS named — keeps the override surface from accepting `pink` and `tomato` and a hundred other browser-renderable names that drift from the warm-paper aesthetic.

### PR(c) — Field Notes treatments + SVGs + B6 lint

20. **Tokens.css is the single source of truth — no fallback hexes anywhere.** Every fallback-hex `var(--outpost-foo, #hex)` in `pwa/src/styles/structure.css` was eliminated (7 literals at lines 81, 92, 93, 108, 109, 835 in pre-PR(c) state). Components reference `var(--outpost-*)` with NO fallback. The B6 lint enforces this in CI; CONTRIBUTING.md "Why B6 matters" documents the rationale (fallback hex still shadows theme overrides on cache miss).
21. **Mode-class scoping in tokens.css.** `.outpost-mode-day` (alone) and `.outpost-mode-system` share a selector list with day-warm-paper values; `.outpost-mode-night` has the night palette; `@media (prefers-color-scheme: dark) { .outpost-mode-system { … } }` switches system mode automatically. Both `pwa/src/styles/tokens.css` and `styles/outpost-tokens.css` carry the blocks; parity verified by `bin/check-tokens-parity.mjs` (190 declarations match post-FY).
22. **Field Notes treatment layer is mode-class-scoped + opt-out-able.** Every treatment selector is `.outpost-mode-{day,night,system} .outpost-tab:not(.outpost-tab--plain)` or similar. Adding `.outpost-tab--plain` (or `--plain` variants for buttons, headings, inputs, radios, voice icon) opts a single instance out of the treatment without disabling mode-scoped tokens.
23. **Voice-pulse reduced-motion exception is intentional.** Every other animation in `structure.css` stops under `prefers-reduced-motion: reduce`. Voice pulse continues at slower cycle (3s vs 1.5s) and reduced amplitude (0.78 vs 0.55 mid-opacity) — it conveys the functional "recording right now" state; removal would harm usability more than the dampened motion disturbs vestibular sensitivity. Rationale shipped as inline CSS comment immediately above the `@media (prefers-reduced-motion: reduce)` block so future readers see it without git-history archaeology.
24. **Five SVG assets ship in `assets/svg/`.** `radio-idle.svg`, `radio-selected.svg`, `heading-swoosh.svg`, `halftone-pattern.svg`, `voice-mic-stamp.svg`. All use `currentColor` so the active mode's text-color flows through. Hand-drawn aesthetic via single-stroke paths; halftone uses 4-circle 12×12 tile that repeats.
25. **B6 catches BOTH direct hex AND fallback hex.** Regex `#[0-9a-fA-F]{3,8}\b` over `pwa/src/styles/structure.css`. Token files (`pwa/src/styles/tokens.css`, `styles/outpost-tokens.css`) are scope-exempt by design — they ARE the source of truth. Demo verified: direct `#abc123` and `var(--outpost-foo, #abc123)` both fail; clean tree passes.
26. **Convention divergences from FY prompt.** Prompt: `Token_Resolver.php`, `Theme_Json_Reader.php`, `Contrast.php`, `Mode_Controller.php`, `Appearance_REST_Controller.php`, `Appearance_Settings_Page.php`, `tests/theming/`. Actual repo conventions: kebab-case files (`class-token-resolver.php` etc.) under `includes/theming/`; admin page under `includes/admin/`; PSR-4 test namespace `Outpost\Tests\Theming\` mapped to `tests/theming/`. Continues F1–F16 / FX pattern.
27. **No version bump for FY (any of a/b/c).** PR(a) ships resolver foundation (no observable change). PR(b) ships settings page + REST endpoints (admin surface only — non-admin users see nothing). PR(c) ships treatments + SVGs + lint (treatments only render under a mode class; mode class is set per-user via the settings page from PR(b); zero-user-action default for existing installs preserves status quo). Version bump comes when default-mode-on lands in a future session.
28. **`--plain` modifier classes are PUBLIC API extension points.** Site owners and theme authors can opt any single instance out of Field Notes treatments by adding the matching `--plain` class. Seven hooks: `outpost-tab--plain`, `outpost-heading--plain` (covers both h1 display-font + h2 swoosh underline), `outpost-input--plain`, `outpost-textarea--plain`, `outpost-radio--plain`, `outpost-button--plain`, `outpost-voice-button--plain`. Mechanism is class-based (`:not(.outpost-foo--plain)`), per-instance — opting one element out doesn't affect siblings, doesn't disable mode-scoped paint tokens (background/text/border still flow through the active mode), only suppresses Field Notes character (rotation, decorative SVGs, swoosh, uppercase letter-spacing). Use cases: third-party blocks embedded in the composer subtree, error-state callouts that want regular button rendering, custom widget surfaces with their own visual identity. Documented in CONTRIBUTING.md "Field Notes treatments — opting out" section. Rename or removal is a major version bump.
29. **Stack-merge sequencing — retarget downstream PRs BEFORE deleting the upstream branch.** When merging a stack of PRs (PR(a) → PR(b) → PR(c)) that base on each other, GitHub auto-closes any PR whose base branch is deleted. `gh pr merge --squash --delete-branch` is the standard pattern, but for stacked PRs it triggers a cascade: merging PR(a) with `--delete-branch` deletes the head branch of PR(a), which is the BASE of PR(b), which auto-closes PR(b). Recovery requires pushing a placeholder branch at main's tip → `gh pr reopen` → `gh pr edit --base main` → delete the placeholder → rebase the head onto main. Three round-trips per cascade. Prevention: BEFORE merging the upstream PR, run `gh pr edit <next-pr> --base main` on every downstream PR in the stack. Then merging the upstream's branch leaves no dependent PR pointing at it. Discovered during FY-Theming merge sequence (PR #25 → PR #26 → PR #27); paid the recovery dance twice before retargeting policy got captured. Any future stacked-PR merge — Phase G+, post-launch refactors, RFC stacks — should retarget before merging the upstream.
