## Session F3 — Locked Decisions (shipped)

Closed 2026-05-04. Verifies image alt-text passthrough Outpost → Micropub plugin → WP attachments → ActivityPub plugin transformer. Investigation surfaced an upstream Micropub-plugin gap; F3 ships the Outpost-side fix.

1. **Investigation finding: Outpost is a Micropub CLIENT.** No PHP photo upload handler exists in the Outpost repo — the prompt referenced `Micropub_Server.php`, but image uploads land at the Shanske Micropub plugin's `/wp-json/micropub/1.0/media` endpoint. Outpost's photo path is purely client-side (`pwa/src/lib/photo.ts` for processing, `pwa/src/lib/micropub.ts` for upload + create-post requests). What Outpost owns is the SHAPE of the Micropub create request and the `after_micropub` bridge hook.
2. **Investigation finding: the AP plugin reads `_wp_attachment_image_alt` for `attachment[].name`.** Confirmed against `Automattic/wordpress-activitypub` — `class-base.php::transform_attachment()` calls `get_post_meta( $attachment_id, '_wp_attachment_image_alt', true )` and stores it (HTML-stripped + entity-decoded) at `attachment[].name`. The transformer also runs `do_shortcode($content)` on post_content before parsing img tags, so the Micropub plugin's `[gallery]` shortcode output works correctly.
3. **Investigation finding: the upstream Micropub plugin does NOT write `_wp_attachment_image_alt`.** Confirmed against `indieweb/wordpress-micropub`. Two failure modes:
   - Structured photo entries `{ value, alt }` are recognized, but the alt is passed to `media_sideload_url($url, $post_id, $title)` which stores it as `post_title` rather than `_wp_attachment_image_alt`.
   - The parallel `mp-photo-alt` array convention isn't honored at all — Outpost client requests using that shape silently drop alt text.
   Net effect: every Outpost-originated Photo or Gallery post syndicated via the AP plugin federates with empty alt text. Accessibility regression for every user. Filed as a follow-up to consider an upstream PR; Outpost ships the fix in-tree below.
4. **Outpost-side bridge: `Outpost_Micropub_Bridges::apply_photo_alt_text()`.** Hooks the existing `after_micropub` action at priority 20 (alongside the other bridges) and writes `_wp_attachment_image_alt` for every photo URL in the request that resolves to an attachment via `attachment_url_to_postid()` and is parented by the post being created (or has post_parent=0). Reads BOTH photo shapes — structured `{ value, alt }` AND parallel `mp-photo-alt` arrays — so legacy clients work too. The structured shape wins per-entry when both are present (matches the Micropub spec's stated precedence).
5. **Empty alt strings are persisted, not skipped.** AP spec accepts empty `attachment[].name`; some downstream AP consumers default to URL/filename when the field is missing entirely. An explicit empty value beats a missing field.
6. **Defensive parent check.** The bridge skips attachments whose `post_parent` resolves to a different post — defends against URL collisions or third-party media libraries shared across posts. Attachments with `post_parent = 0` (orphan during early Micropub processing) are accepted.
7. **Locked: `_wp_attachment_image_alt` is the canonical alt-text storage.** Any future Outpost code that touches image alt text writes there, not to a custom Outpost meta key. The AP plugin (and WordPress core's `wp_get_attachment_image()`) both read from this key; alternative keys would require fork-style coordination.
8. **Locked: gallery posts emit one attachment per image, not a composite.** The Micropub plugin already does this correctly via `media_handle_upload`/`media_sideload_url` per photo entry; F3 doesn't change it but locks the contract.
9. **Locked: post_content for Photo posts is the `[gallery size=full columns=1]` shortcode the Micropub plugin emits.** Outpost does NOT override this. The AP plugin's `do_shortcode()` call renders it, the rendered img tags then get parsed. Future write-shape sessions that consider switching to `core/image` blocks must verify the AP transformer still finds the attachments via `attachment_url_to_postid()` on the rendered URLs.
10. **Companion_ActivityPub caveats array gets a second entry** noting that alt-text passthrough requires Outpost active alongside the AP plugin. Without the bridge, even a correct Outpost client request loses alt text upstream.
11. **Test fixtures: `tests/fixtures/sample-photo-200x200.jpg` and `-alt.jpg`.** Generated test patterns via PHP/GD (gray + blue solid backgrounds with a stripe and circle), ~2 KB each. Generic, no personal photos. Reserved for the wp-env-backed integration tests when those land.

Each stub's docblock spells out the exact steps. They run via `markTestSkipped` today.

Unit tests cover the bridge across 7 paths (structured shape, parallel-array shape, empty-alt-persists, foreign-parent-skipped, unresolvable-URL-skipped, no-photo-noop, orphan-attachment-accepted) and a direct `collect_photo_alt_pairs()` resolver test. No version bump — F3 ships defensive server-side behavior that activates on the next photo post; existing Outpost installs benefit immediately on plugin update without any user action.
