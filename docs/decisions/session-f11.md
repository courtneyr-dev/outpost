## Session F11 — Locked Decisions (shipped)

Closed 2026-05-04. Replaces F10's iOS stub with real strategy-chain handler. Per-platform fallback chains drive everything: navigator_share_files → app_url_scheme → web_intent → manual. F11 modules ship; the composer chip-strip integration that wires Android (F10) + iOS (F11) together remains deferred (consistent with F10 #13 stance).

1. **iOS strategy chains are arrays of strategy names; F9's string-typed `ios_strategy` migrated to array.** F9 originally declared `ios_strategy` as a string ('navigator_share_files', 'web_intent', etc.). F11 migrates it to an array — each platform's chain like `['navigator_share_files', 'app_url_scheme', 'manual']` walked in order by the runner. Backward-compatible: a string `ios_strategy` value coerces to a single-element array at config-validation time. Site owners adopting F11 don't have to migrate immediately.
2. **`app_url_scheme` replaced F9's `ios_url`.** F9's `ios_url` field mixed iOS app URL schemes (`instagram://`) and iOS web intent URLs (`https://twitter.com/intent/tweet`). F11 separates these: `app_url_scheme` for the iOS app URL scheme; `web_intent_url` (already F9) for the iOS-friendly web URL. Backward-compat: `ios_url` from F9 silently maps to `app_url_scheme` at validation time.
3. **Per-platform iOS chains per Doc 1 §4.4.** Instagram (feed + Stories), LinkedIn, TikTok, Flickr-manual use `[navigator_share_files, app_url_scheme, manual]`. Facebook, X, Threads, Pinterest, Reddit-manual use `[navigator_share_files, web_intent, manual]`. Every chain starts with `navigator_share_files` (best UX when in PWA) and terminates with `manual` (always-succeeds worst case). Cross-platform invariants are test-enforced — `IosStrategyChainsTest` catches drift.
4. **The strategy chain is platform-routed; the runner is a tiny dispatcher.** `StrategyRunner.run_strategy_chain()` walks the chain, calls each strategy's handler, stops at the first non-`rejected` outcome. `'aborted'` (user cancelled) does NOT fall through — tapping cancel on the share sheet must NOT chain into a URL scheme launch. `'fired'` stops the chain. Defensive default: if the chain exhausts without firing, the runner returns `outcome='aborted', strategy='manual'`.
5. **App URL scheme uses 1500ms visibility-change heuristic.** iOS doesn't return useful errors for URL schemes — visibilitychange / pagehide is the standard pattern. The strategy fires `env.navigate(url)` AFTER subscribing the listener, then races the listener against a 1500ms timeout. The pattern is timing-sensitive; real-device testing will tune. Limitations documented in the strategy file's docblock.
6. **`navigator.share` on iOS is PWA-only for files.** iOS Safari 16.4+ supports `navigator.share({ files })` only inside an installed PWA. F11 detects PWA mode via `is_pwa_installed_on_ios()` (matchMedia('(display-mode: standalone)') OR legacy `navigator.standalone === true`). The PWA POSTs `in_pwa_mode` to `/manual-share/intent`; the server propagates it in the iOS payload. The handler's `filter_chain_by_capabilities` strips `navigator_share_files` when `in_pwa_mode === false` so the runner doesn't waste time fetching files only to discover the API silently drops them.
7. **AbortError is a hard stop, not a fall-through.** When `navigator.share` rejects with `AbortError` (user tapped cancel on the system share sheet), the strategy returns `'aborted'` — NOT `'rejected'`. The runner respects that and stops. Other rejection reasons (NotAllowedError, etc.) return `'rejected'` and the chain continues.
8. **Manual fallback is a real UX, not an error.** `try_manual_fallback` invokes `env.show_manual_modal(props)` which mounts the `ManualShareFallbackModal` component. The modal renders Save Image (when files present), Open App (when platform homepage URL exists), Done buttons. User-explicit dismiss via Done/Save/Open returns `'fired'`; close-without-action returns `'aborted'`. `PLATFORM_HOMEPAGE` map in the strategy hard-codes the platform brand URLs (instagram.com, threads.net, etc.) — not user-specific instances.
9. **Audit-log strategy mapping projects fine-grained iOS chain entries onto coarse storage labels.** The audit log accepts `navigator_share`, `intent_url`, `two_tap_fallback` — three coarse labels. F11's `map_strategy_to_audit_label` projects: `navigator_share_files` → `navigator_share`; `app_url_scheme` + `web_intent` → `intent_url`; `manual` → `two_tap_fallback`. The PWA's telemetry POST (already from F10) updates the entry with the actual fired strategy at completion time.
10. **Async strategy-chain re-entrancy fix.** During F11 test development, the synchronous-test-mock for `set_timeout` triggered a TDZ error: the timer callback fired before `const timer_handle` was initialized. Fix: declare `timer_handle` as `let` initialized to `undefined`; guard `clear_timeout` with `undefined !== timer_handle`; check `resolved` flag before navigating. Captured here so future strategies that race callbacks against timeouts use the working pattern.
11. **PWA composer chip-strip rendering UI remains deferred.** Same rationale as F10 #13: F11 ships the iOS handler + strategies + modal as testable building blocks; the composer-side "tap chip → execute_ios_share" wiring lands when F12 (silo URL capture) provides the after-share UX hook. F12's `prompt_for_silo_url` flow needs the chip-strip to display the prompt; that's the natural integration point.
12. **Live device verification deferred to one-time check.** Per acceptance criterion #15, manually verify on a real iOS device: share Photo post to Instagram via the manual-share chip, confirm strategy chain works end-to-end (PWA Safari + non-PWA Safari paths). Not a CI requirement; documented in the F11 PR as the validation that the timing-sensitive visibility heuristic actually fires for real users.
